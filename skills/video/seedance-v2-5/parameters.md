# Seedance 2.5 — Parameters

All values below are from ByteDance's own ModelArk documentation — the Dreamina Seedance 2.5 prompt
guide, the capabilities overview table, and the published API examples.

> **Two audiences for this file.** A director generating in a UI needs the *ceilings and behaviours* —
> duration range, resolution, asset budgets, what locks and why. The exact parameter names, roles and
> endpoint below matter to **the integration layer**, which does drive the API and will hit every one of these
> constraints. Both are kept here rather than split, because the constraints are the same either way;
> only the vocabulary differs.

### ⚠️ Resolution is a regression, not an upgrade

**Seedance 2.5 tops out at 720p. Seedance 2.0 offers 1080p and 4K.**

This is counter-intuitive and consequential. Marketing copy on ByteDance's consumer surfaces advertises
4K for Seedance 2.5; that is a consumer-app claim and does not describe this model's output
specification. If a finishing-grade master is the requirement, **that is a routing decision** — see
`README.md`.

## Core parameters

| Parameter | Type | Values | Notes |
|---|---|---|---|
| `model` | string | `dreamina-seedance-2-5-260628` | |
| `content[]` | array | `{type: "text", text: …}` and `{type: "image_url", image_url: {url}, role: …}` | The prompt is one `text` item |
| `generate_audio` | boolean | `true` / `false` | Native synchronized audio |
| `ratio` | string | `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16`, `adaptive` | See below |
| `duration` | integer | 4–30, or `-1` | `-1` = model picks the optimal duration in range |
| `output_format` | string | `mp4`, `mov` | **`mov` recommended for editing and extension** |

### `content.role` values

`first_frame` · `last_frame` · `reference_image` · `reference_video` · `reference_audio`

The role determines whether a task is locked — see below.

### Aspect ratio, precisely

The `ratio` **enum is the same seven values on 2.5 and 2.0.** The often-repeated claim that "2.5
supports any ratio between 0.4 and 2.5" is true but needs its qualifier: under `adaptive`, 2.5 can
land on any ratio in **[0.4, 2.5]** *by inheriting it from the input assets*. Seedance 2.0 is confined
to its six fixed ratios regardless.

So: flexible ratios come from the assets, not from the parameter.

## Locked vs unlocked tasks

Seedance 2.5 classifies tasks by whether input assets lock output properties. **Seedance 2.0 makes no
such distinction.**

**Locked** — the input asset is placed as a real segment on the output timeline, so the output adapts
to it.

| Task | `ratio` | `duration` | Roles | Prompt trigger required |
|---|---|---|---|---|
| **Editing** | must be `adaptive` — inherits the edited video's ratio | must be `-1` — inherits the edited video's length | `reference_image` / `reference_video` / `reference_audio` | `edit video`, `add`, `insert`, `remove`, `delete`, `modify`, `replace`, `change to` |
| **First / first-and-last frame** | must be `adaptive` — inherits the first frame's ratio | director's choice | `first_frame`, `last_frame` | — |
| **Extension** | must be `adaptive` — inherits the extended video's ratio | director's choice | `reference_image` / `reference_video` / `reference_audio` | `extend forward`, `extend backward`, `continue`, `continue from`, `extend the story` |

**Unlocked** — the input is a semantic reference only; ratio and duration are the director's choice.
Covers reference tasks, storyboards and keyframes.

### Editing duration tolerance

Output duration may differ from input by **up to about 0.3 seconds**. This compresses transition
frames only; content stays aligned and complete. **When the input was itself generated by Seedance
2.5, there is no difference at all.**

### Last-frame aspect ratio

If the last frame's ratio differs from the first frame's, **it will be stretched.** Use matching
ratios.

## Reference assets

| Category | Max | Limits |
|---|---|---|
| Images | **30** | Resolution up to 4K |
| Videos | **10** | Combined total ≤30 s |
| Audio | **10** | Combined total ≤30 s |

**50 assets total** — the largest reference budget in the video catalogue. Compare `minimax-h3` at 12
combined and `veo-v3` at 3 images.

### ByteDance's own stability recommendations

These are guidance for *reliable* results, not hard caps — exceeding them works but may need retries.

| Question | Recommendation |
|---|---|
| Subjects via **audio/video** reference | **1–5** works well; 6–10 possible, less stable |
| Duration of subject audio/video references | **5–10 s** works better; longer reduces stability |
| Subjects via **image** reference | **1–8** works well; 9–12 possible, less stable |
| Multi-viewpoint images | For 1–5 subjects, single- and multi-view both fine. **Above 5 subjects, single-view is more stable** — split viewpoints into separate images rather than one image containing several |
| Storyboard panels | **≤15 panels.** Stick-figure or line-art preferred. Avoid text on the board |
| 3D clay-model detail | **Coarse-grained is better.** Simple geometric primitives for people, objects and animals |
| Video length for editing | **≤20 s** produces better results |
| Reference images when editing | **1–5** works well; 6–8 possible, less stable |
| Format for extension | **`mov` for both input and output**, for best audio-visual continuity |

## Prompt length

**ByteDance publishes no character or token limit for Seedance 2.5.**

No length ceiling is asserted here for that reason.

**On working length — an earlier figure in circulation is wrong.** A "60–300 words" community range
circulates and is far too narrow: ByteDance's own published API examples run **400–700 words**, with
full shot lists, per-shot dialogue, timestamps and style blocks. Long, structured prompts are the
documented house style for this model, not an anti-pattern.

What degrades output is *unstructured* length, not length itself. Use the recommended structure.

---

## Negative control

**No `negative_prompt` parameter exists.** In-prompt negation is documented, but **narrowly scoped**:

> *"Use positive descriptions whenever possible. Negative constraints are supported for subtitles and
> audio control, such as 'no subtitles' and 'no BGM.'"*

Documented as supported:

- **Subtitles** — `No subtitles.` / `Do not add subtitles.`
- **Audio, at fine granularity** — sound effects, background music and dialogue separately.
  `No BGM; generate only environmental sounds and action sounds.` / `No audio.`

Broader exclusions appear in ByteDance's own examples (`no text overlays, no dissolve transitions, no
duplicated people, only hard cuts`, and `[Strictly exclude]` style blocks) and work in practice, but
sit outside the documented guarantee.

## Official prompt-engineering skill

ByteDance ships a first-party prompt-optimisation skill for this model:

```
npx --yes skills@latest add \
  "https://arkdocs-en.tos-ap-southeast-1.volces.com/skills/" \
  --skill sd25-pe --yes
```

Invoked as `/sd25-pe` + prompt. Worth knowing about — it is the vendor's own tooling for the same job
this skill does, and a useful cross-check on anything ambiguous.
